# Reporting module

Responsibilities, owned tables, events emitted/consumed: see docs/architecture/DOMAIN_MODEL_AND_MODULE_BOUNDARIES.md.
Cross-module use is limited to Contracts, DTOs, Enums and Events (BD-11).

* Phase 10, slice 1: **`Metrics/`** holds every metric once (`MetricDefinition`, one class each, and `MetricCatalogue`); dashboards, reports and exports ask the catalogue. The explaining words are in `resources/lang/{en,bn}/metrics.php`.
* **Summary tables** `report_daily_sales`, `report_daily_payments`, `report_day_status` (see the data dictionary). `Actions/RefreshReportDay` replaces one Dhaka day as a whole, under the day's lock; it reads Orders' `SalesFigures` and Payments' `PaymentFigures` Contracts only. `Jobs/RefreshRecentReportsJob` (every 15 minutes: today and yesterday) and `Jobs/RefreshWindowReportsJob` (02:45: the last 35 days); `php artisan reports:rebuild FROM TO` for older days (audited).
* Screen: `/admin/reports/sales` (`reports.view`; `reports.finance.view` for money received, given back and net sales). `Services/ReportReader` reads the summary only; `Services/ReportDays` turns a Dhaka day into UTC bounds. Settings in `config/reporting.php`.
* Recognised revenue is not built: the accountant has to confirm the rule first.
* Phase 10, slice 2: **`Reports/`** holds the report catalogue (`ReportDefinition`, one class per report, `ReportCatalogue`); the screen (`/admin/reports`, `/admin/reports/{code}`) and the CSV export read the same definition. Other modules give their figures through read Contracts (Payments `CodAgingFigures`, Inventory `StockReportFigures`). **Files**: `report_exports` + `Actions/RequestReportExport` → `Jobs/BuildReportExportJob` (`Actions/BuildReportExport`) → `Actions/DownloadReportExport`; `Actions/ExpireReportExports` runs hourly. `php artisan reports:build-export ID` builds a waiting file by hand. Files live on `config('reporting.exports.disk')` (private) for `expires_days` days. A new report: add the class to `ReportCatalogue::REPORTS`, its words to `resources/lang/{en,bn}/catalogue.php`, and a row to the permission matrix in `ReportCatalogueTest` (a test fails until you do).
* Phase 10, slice 2b: reports `best_sellers`, `sales_by_product`, `sales_by_category`, `sales_by_brand` (open to `reports.view`) and `tax_summary` (also `reports.finance.view`). Summary tables `report_daily_products` and `report_daily_tax` are replaced with the other day tables by `RefreshReportDay`. `Services/ProductSales` adds variants into products and groups them by primary category or brand (looked up when the report opens, through Catalog's `ProductGroupings`); `Services/Ratio` is the one share formula. New metrics: units sold, units returned, return rate, sales after discounts.
